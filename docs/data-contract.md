# 羊毛数据规格（流水线 × 栏目对照）

字段合同自 2026-10-01 起生效；现役口径校对至 2026-10-12。目标：**一条羊毛审一次，网站所有栏目、统计和推送都一次性正确**，不再事后返工补字段。

代码里的共同来源：`src/shared/spec.ts`（字段检查、栏目清单、标签词表）与 `src/shared/valuation.ts`（估值 V1/V2、公开过滤、标准用量、结案及显示口径）。服务器审核、审批卡片“上架前检查”、采集抽取都复用它们。改规格时先改实现，再同步本文。

## 一、流水线

```
信源抓取 → 关键词筛选 → 模型抽取（全部字段）→ 规整（不合规的值修正为合法值，不丢整条）
  → 入库（待审）→ 媒体稿自动搜索官方补证 → 审批卡片“上架前检查”
      ├─ 通过：进入下表列出的全部栏目
      └─ 拒绝：只进入“准确率”统计和模型学习，不出现在任何公开栏目
```

- **拦截（必须补）**：缺了会让某个栏目算错或显示错，审批时“通过”按钮不可用，服务器也会拒绝。
- **提醒（建议补）**：能通过，但列出的栏目会少数据。检查清单写明影响哪些栏目。
- **可选**：缺了只是显示“官方未写明”或通用文案。
- **已上架的条目**也按同一规格检查，缺字段的出现在审批页“已上架、字段待补”，可以直接补。

## 二、字段 → 栏目

**海外网络门槛（2026-10-11管理员纠错）**：国外厂商以及国内厂商的国际版/全球版产品，所有活动的 `requirements` 必须含 `net`（海外网络），并移除 `none`；保留其他实际资格和 `unknown`。国内版独立判断，不能仅按语言、公告渠道或域名后缀判断产品版本。无需信用卡不等于零门槛。此为本站领取条件展示口径，不是官方权益变更；修订理由写内部记录，不刷新官方核验日期、不改变审批状态。

| 字段 | 级别 | 用在哪里 |
|---|---|---|
| 平台 platformId | 拦截（平台须已准入、证据须是该平台官方出处；公众号文章须其 `__biz` 已登记在平台 `wechat`） | 所有栏目；平台页、谁最大方、大方榜、时间线的行、桑基图（平台类型） |
| 标题 title | 拦截（空）/ 提醒（整句英文） | 所有卡片和列表、详情页、墓场、时间线、推送 |
| 类型 type | 拦截（须与截止方式配套） | 今天（限时）/ 常驻额度库 / 申请制 的划分，配色，桑基图，新增类型构成，状态规则 |
| 额度 valueText | 拦截（空）/ 提醒（整句英文） | 详情页、推送；没有美元时卡片上直接显示 |
| 门槛 requirements | 拦截（待确认） | 我的条件筛选、全部羊毛门槛筛选、薅度分“门槛低”“国内直领”、四象限横轴、桑基图、推送 |
| 会员资格 membershipRequirement | 新增/修改会员资格及批准时校验 | 标准目录ID、任一/全部、排除项及限制；公开门槛投影、个人会员匹配、身份terms-v2；旧批准条目的needs_review表示自动匹配未完成，不是福利待审 |
| 首 30 天参考美元 usdEstimate | 提醒（未估值）；经核实公测未定价/无法折算可结案 | 同一窗口内排序、四象限、薅度分、我的参考权益；官方口径与用量估算分别合计，不表示现金或已经省下的金额 |
| 真实权益上限 usdMax | 可选；不能小于确定金额 | 申请制保存完整资助周期的真实最高可申请额，与 valuation.inputs.fullApplyMax 一致；首30天上限另存 inputs.first30Max，释放安排未知留 null。无保底时 usdEstimate=null；模型成本范围不放在这里 |
| 估值 valuation | 可选（旧记录待迁移）；已填但状态/版本/金额不合法时拦截 | 方法、周期、完整权益价值、公式、价格来源、必要假设、基准模型与计价覆盖。美元字段必须一致；内部理由/问题/旧值只放 reviewMemo |
| 领取开始 claimStart | 拦截（已结束的限时活动）/ 提醒（其他限时活动） | 日历（每天有效）、时间线、即将开始、羊毛墓场存活天数、平台发放历史、每周新增和大方榜（按活动开始的日子）、节日往年发过 |
| 领取截止 claimEnd + 截止方式 endKind | 提醒（限时活动截止未知） | 状态（进行中 / 即将结束 / 已结束）、倒计时、3 天内结束、加急推送、日历结束点、时间线、墓场、每周结束数 |
| 官方时区 sourceTz | 必填（默认 UTC） | 所有日期换算成访问者本地时间和北京时间 |
| 免费模型 models | 提醒（免费类条目点名了模型却没填） | 按模型找 |
| 标签 tags | — | 重置时钟（额度重置）；以后的邀请、折扣、每日刷新筛选 |
| 官方发布时间 publishedAt | 提醒（额度重置） | 重置时钟（星期 × 时段分布）、详情页时间轴；没有开始日期时作为“活动出现的日子” |
| 模态 modalities（文本·编程 / 图像 / 视频 / 音频；文本和编程不区分） | 必填 | 今天“按模态分”、常驻额度矩阵、全部羊毛模态筛选 |
| 领取方式 claimMethod | 必填 | 详情页、全部羊毛筛选、桑基图、薅度分“好领取”、推送 |
| 适用对象 audience | 提醒（未写明） | 详情页、推送 |
| 额度有效期 creditValidity | 可选 | 详情页、推送 |
| 领取步骤 steps | 可选 | 详情页、推送（没有时按领取方式显示通用步骤） |
| 官方证据 evidence（链接、级别、原文摘录） | 拦截（媒体转述不能上架，检查清单同样显示为拦截；管理员实测可以）/ 提醒（缺权益原文） | 详情页“官方证据”、薅度分“信源可信”、推送“官方原文”“信源” |
| 牧场心得 offer_comments | 用户公开留言 | 详情页共同列表；管理员署名 admin，匿名访客署名羊毛党加六位数字。adminNote 仅兼容原管理员心得编辑和推送 |
| 核验记录 reviewMemo | 仅管理员 | 审批卡片；公开接口不输出 |

系统字段（不用审核时填）：发现时间 discoveredAt（详情页“系统发现”）、最近核验 lastVerifiedAt / verifyResult（历史证据记录，不撤销已批准条款）、确认停止领取 withdrawnAt / withdrawnReason（结束、墓场）、首个渠道 firstChannel 和来源信源 sourceId（准确率统计、自动上架）。

**公开牧场心得（2026-10-12）**：详情页的管理员与访客留言使用同一个 `offer_comments` 列表；访客无需登录，服务端分配唯一的六位随机数字，显示为“羊毛党345876”这类名字，通过 HttpOnly / SameSite=Strict Cookie 保留一年。清除 Cookie、到期或换浏览器会获得新身份，不承诺跨设备识别。管理员新留言由管理员权限验证后署名 `admin`，不接受访客自报身份。每条 1–500 字，直接公开，以纯文本展示，不作官方证据或管理员亲测依据；原有 adminNote 迁入同一列表，其旧编辑接口事务同步，原字段保留用于既有推送兼容。留言不修改条款、审核状态或 tested 标记。管理员可从详情页软删除，公开接口不再返回；待审、拒绝条目和未准入平台不能公开读写留言。

**会员门槛命名（2026-10-11）**：`member:` 后的每个套餐名都须包含实际产品/平台名称，例如 `Claude Pro`、`n8n Cloud Pro`。泛称付费订阅也须带产品名；并列档位和跨平台资格逐个写全，保留价格与资格限制，不靠页面上下文识别属于哪个会员。“我已有的会员”直接汇总该字段，因此须修改条目及当前待审候选的数据，不能只在界面补标签。

**选择式会员资格**：后台从标准目录选择产品与套餐，会员自然语言不再作为个人筛选键。`membershipRequirement` 以membership-v1保存状态、目录修订、anyOf/allOf及限制，目录同名别名限定产品上下文；member:仅为兼容展示投影。任一/全部与排除条件由共享模块解释，缺少订阅信息返回待确认。自动采集不能确认目录或直接批准会员资格。已批准旧条目的 `needs_review` 表示个人会员自动匹配尚未结构化，不是福利重新待审；原条件和批准状态保留，不重抓旧证据或要求管理员逐条重新批准。个人“只看确定符合的”暂不含这种未知匹配，关闭筛选可按原条件查看；新待审或真实资格变更仍须确认目录、组合和限制。审核保存无关字段不清空既有会员条件。目录版本检查同时覆盖保存、批准和提交事务。

会员身份进入terms-v2；V1历史事实与哈希保留，确定等价的迁移创建V2基线及membership_version_migrations映射，不改历史决定、不产生通知。未确认旧资格不建立等价映射。已确认结构的展示顺序或目录名称变化不算新权益；资格逻辑实际变化仍需审核。

**公开文案与内部审核分开（2026-10-09）**：`title`、`valueText`、`steps`、`creditValidity`面向领取福利的用户，只写权益、领取操作、实际资格、用量、费用及期限。核验经过、来源缺口、旧记录误归/误估、重复判定、审批待办、估值取舍写入`reviewMemo`或审核理由，不写入公开简介、步骤或公开的`adminNote`。未知资格/金额仍保留未知字段及证据门槛，不能借清理文案把未证实线索变成确定承诺。入口不可用、领取已结束、绑卡、地区限制与自动续费是用户需要知道的事实，应保留。历史人工纠错及完整修订记录仅通过管理员接口读取。

**首页到期提醒（2026-10-12）**：倒计时独立于“当前可领”统计，展示未来7天内到期的已批准限时活动，不截断为5条。官方具体日期按原时区计时；明确一周限免但精确截止未知时，可按已记录公告时间/活动开始日生成“约”的截止估算，日精度公告保留一天的不确定区间，现有已批准基线的展示估算不写回claimEnd，也不冒充官方时刻。旧抓取失败不改变已批准条目的可领状态；个人领取/注册/激活后的额度有效期不能当活动截止，未批准、已结束、未开始及无周期锚点的不展示。

**采集的通用活动周期自动截止（2026-10-11）**：共享`fillCampaignDeadline`在采集草稿和`collectedOfferIn`入库边界执行。须为全局限时活动、有可信周期原文、有完整开始日/公告时间；支持分钟/小时/固定天数/周/自然月/自然年及明确复合周期，自然月/年按源时区推进、月底缺失对应日取月末；自动补claimEnd与endKind=date，evidence.claimEndDerivation保存components（周期数量与单位，兼容旧durationDays）、原文/URL、anchorField/anchorValue、日期或时刻精度及推算时刻。日期推算元数据随evidence JSON存储，无独立迁移。展示必须标截止估算。明确截止优先；个人激活后的有效期不填活动截止；媒体/无周期原文/无锚点不推算。普通offerIn及人工已审基线校验不自动回填，避免无关编辑改写旧版。官方identityFacts仍按独立证据生成，不从推算展示日期倒推。

## 四、统一口径

- **活动出现的日子**：官方开始日期 → 官方发布时间 → 系统发现时间，取第一个有的。“新增”类统计（本周新增、每周新增、大方榜）都按它算，补录的历史活动不会算成本周新增。
- **已审核版本与更新依据**：approved所有字段以管理员通过的版本为准。采集器须随请求附同一官方页面完整正文sourceText（不由模型生成、不写入公开条目）；仅当旧权益/资格/有效期原句已不在当前正文、对应新原句可在正文定位，并能在同一事实槽证明额度、日期或可识别资格发生明确替换，才允许生成更新提案。旧句缺失本身、多语言、数字格式及截句变化不足以证明政策改变；固定X/status公告不自动重开，未识别语义交人工。旧原文仍在、只换摘录、整页哈希变化、金额重新估算或没有可靠正文时，保留通过版本，不产生重审。换证据入口、缺旧原文基线或管理员实测条目须另行人工核查，不能用模型推测放行。
- **拒绝更新记忆**：拒绝时先将该版证据和差异保存到rejected_offer_updates，再移除队列项；再次抓到被拒版本仍存在的相同官方条款时不重新提交。新官方条款确实取代旧条款才可另提更新，真实新一轮活动仍按活动身份去重规则判断。
- **候选合并**：现有人工修改字段持续保留；经过官方变化验证的valueText及证据允许一同更新为待审候选，批准后成为新基线。模型漏抽的已知日期/美元不清空；管理员已审 valuation 及对应美元不能由抽取重算或清空。人工编辑中的提案不因一次无变化抽取而删除。合并后重新校验完整字段合同与估值一致性，不合规则返回错误而不入队。自动上架信源也不能跳过已有条目的审核。
- **比对边界**：字符串统一全半角与空白，数组按集合比较；这不是语义判断。同样数字但不同含义的额度文案、人工锁定字段的真实变化，可能需管理员主动核实并编辑，不能宣传为“所有实际条款变化都会自动发现”。仅证据摘录、页面哈希和抓取时间变化不生成审批任务。
- **批准与核验**：批准保留已审核条款版本。批准后停止定期重抓该条目的旧证据；历史抓取失败、逐字匹配失败或核验时间变旧仅保留为诊断记录，不撤销批准，也不产生重新审批任务。新发现的明确业务变化仍形成待审更新，须人工决定。
- **状态**：`src/shared/lifecycle.ts` 的 `liveStatus` 是唯一规则，网站 `statusOf` 与之一致。已批准条目以开始日、官方截止日及明确撤回决定状态：截止前维持可领，截止后按发放方时区自动进入历史。截止未知或常驻的条目不能按核验年龄推断过期，页面保留未知提示；发现明确撤回时管理员可提前结束。
- **价值 V1/V2**：美元表示领取者权益的购买参考价值，以领取/激活后的月度窗口比较（技术窗口最多30天）；前端显示“月度参考价值”。usdEstimate映射该窗口，usdMax只保存真实权益或申请上限，fullValue另存完整权益。一次性$100即使7天有效仍记$100，不除以12或按7/30缩减；一年会员按月度和完整时长分别定价，不重复叠加模型。官方面额/对应购买价优先；普通场景仍受覆盖时长与真实额度限制。V2管理员明确采用或已授权自动规则生成的套餐或替代模型参照另记benchmarkType并标provisional，不冒充官方面额，不声明未证实的积分兑换关系或免费覆盖量。详见[方案V2](plans/benefit-valuation-and-field-completion-v2.md)。
- **定价依据 V1**：本平台相同权益官方售价/加购价 → 同版本同规格原厂官方价 → 匹配的 OpenRouter 实际付费价 → 无可靠价格则留空。平台积分不能借用其他平台平均积分费率；本平台没有加购价时取适用套餐的最低单位费率。人民币等非美元保存汇率、来源及日期，不把固定 7.1 当现行事实。原厂/OpenRouter 单价仅能解释匹配模型用量，不能代替整个工具/会员售价；乘标准用量仍归 scenario。
- **标准用量 V1**：每 30 天文本输入 100 万/输出 20 万 Token、编程输入 1,000 万/输出 100 万 Token、图像 100 张、视频 600 秒生成素材、转写 1,200 分钟、语音合成 10,000 字符。质量/尺寸/模式要匹配；未知持续时间须公开 30 天假设。多模型按同场景成本中位选择，偶数取中间较低者；别名/快照先去重，无价模型不当零，缺价覆盖标 provisional。共享预算只计一次，多模态默认主要用途，独立额度的场景总工作量仍受标准用量限制。
- **申请周期 V1/V2**：period=apply_max；usdMax及inputs.fullApplyMax表示完整计划真实申请上限，inputs.first30Max只表示按已核实释放安排在月度窗口能获得的上限。无保底usdEstimate=null，释放安排未知first30Max=null。V2经管理员采用的使用方案可以把成本存usdEstimate，但须benchmarkType、provisional，所有真实上限字段仍null；卡片和月度图以“月度使用方案参考”单列，不进完整上限图或普通合计，不能显示为确定赠金。
- **汇总与评分 V1/V2**：只纳入合法、金额一致且status=priced/provisional的V1/V2元数据。官方价格口径与用量估算分别合计；V2基准卡片另标套餐价格参照/模型成本参照，不合成无说明总额。每条同一窗口计一次，申请独立；使用方案成本不进入申请完整上限图。旧数字可标旧参考值，迁移前不入金额统计。无价、未裁定、旧数字与申请上限不按最低价值计分，去掉价值维度后按其余五维重新分配权重；真实已定价$0仍是数值。
- **美元字段结案 V1**：经核实的 beta_unpriced/unpriceable 保存来源与 reviewedAt，所有金额留 null，关闭美元提醒；needs_judgment、访问失败或来源冲突仍待核实，不写零。真实申请上限明确但无保底可 usdEstimate=null/usdMax=上限。结案只处理美元字段，不绕过资格/证据和已结束活动缺开始日期的拦截。新价格或相关条款变化按授权重新估值，旧值/问题/纠错依据留内部 reviewMemo 及修订记录，审批状态与原权益证据时间分别保留。

- **校验与竞争**：publishedAt只接受合法日精度或带时区ISO；编辑其他字段保留原精度。首次批准仍须满足官方证据与准入门槛；人工批准记录当次证据时间。旧版普通 verify 请求只返回无需复核，不写已批准条目；新提案的写入仍须检查读取时版本。
- **社区补证**：媒体级草稿和更新提案可由固定工作流寻找发放方原文，校验身份、同活动及连续摘录后补字段，仍保持待审。内部official_review不公开、不覆盖memo；sameOccurrenceAs与officialReviewJobId仅为传输控制。队列、重试及恢复统一见[自动官方复核](official-review-workflow.md)。

## 五、通过与拒绝

- **通过**：进入第三节列出的全部栏目；之后的条款变化会生成修订记录，人工改过的字段不会被采集覆盖。
- **已结束但属实**：补全开始和截止日期后**通过**，作为历史数据进入时间线、日历、羊毛墓场、重置时钟、节日往年记录。拒绝理由“旧活动 · 日期查不到”只用于日期实在无法确认的条目。
- **拒绝**：只进入“准确率”统计（拒绝理由、首个渠道）和模型的纠正学习，不出现在任何公开栏目，也不推送。

## 六、现役收录与审核口径

权威业务规则见 [已确认抽取规则](../pipeline/learned-rules.md)，平台特例见 [平台要点](../pipeline/platform-notes.md)。本节给审核者快速决策入口：

- 收实际可量化的 AI Token、积分、次数、API 额度、额外重置/限时加赠，以及身份认证专享的 AI 会员或五折及以下优惠。认证后按月给固定额度用 `standing`，送会员一段时间用 `gift`，有统一活动截止用 `free`；要交材料并由发放方裁量批准的资助用 `apply`，包括固定会员奖品。
- 免费套餐本身的“有限聊天/搜索”、付费套餐内含额度、Relax/Explore、不限量功能、常设阶梯赠送或多送比例不收。2026-09-30 的“超值订阅例外”已被后续规则撤销；OpenCode Go 等不能因额度高于售价就收录。
- 套餐表按月分档的“基础 + 加赠”“每月实得”不因标了“限时”就变成独立福利；须核实套餐之外的活动条件或赠送机制。WorkBuddy 三档月度加赠按套餐自带排除。缺截止日期不是活动不存在的证据，积分有效期不是活动截止。
- Free Tier 与 Free plan/Paid plan 是不同维度；无需先付款的按量计费授权不标 pay，但正文仍注明账户模式及超额收费。一次性注册礼、月度参考素材配额、模型使用扣费分别表述。创业计划的原厂赠金/会员与第三方优惠分别估值，月份精度不补造具体日。
- 消费返利、首购/首次升级/充值触发赠额不收，即使限时、独立发放或翻倍；混合邀请活动只收无需消费的部分。普通折扣与首月优惠不收，首月实付不超过 $1 的近免费体验例外保留。网盘等非 AI 会员、通用云数据库/API 网关试用不收。额外奖励只估赠送，不把本金或整个付费档计为免费价值。
- 号池、共享账号、逆向 API、cookie/session 转售及来源不明中转赠额排除；聚合资讯只产线索。正式证据须为实际发放方，合作方宣传不能代替。`media` 在共享检查与服务器审核中均拦截；`tested` 只在管理员明确确认实测时人工设置。
- 摘录保持原语言，来自同一证据页的连续原文。通常依严格匹配价格计算，无可靠价格留空，不套其他平台积分平均价或旧版模型价格；V2由管理员指定或按已授权自动规则及核价目录采用套餐或替代模型参照，保留假设并标provisional，不扩大收录范围或升级证据。输入输出都为零价才算免费模型，免费期间$0不是正式购买价值。模型数量变化的目录不重复造福利条目。
- 国内手机号/支付条件写正文与步骤；`phone/card/net` 表示海外门槛，不能机械套在国内微信手机号授权上。`unknown` 仍是上架拦截。
- **新建入口去重**：一篇公告多个模型同一种优惠合一条。实现见`src/shared/dedupe.ts`与`reset-event.ts`：除同平台标题/额度相似及数字一致外，还识别无额外范围限定的每日积分/签到别名、相同套餐组的月度API额度及日期后缀、同标题一周窗口内转述；同证据URL同标题误挂其他平台则拦截并指向已通过记录。优先匹配已通过原记录，已拒绝副本不能恢复。保留不同产品/模型模式、付费档、地域、独立机制和真实重置轮次；不能只依赖模型sameAs，也不能宣称启发式覆盖所有语义别名。未知活动或新证据来源仍交人工核查。
- 新待审按发现时间从早到晚，ID 作并列排序；更新提案接在新条目之后、按更新时间倒序。审批卡片的 `approve/history/reject/judge` 是建议，不改变审核状态，也不代替管理员批准。
- `reject` 拒绝新条目；对已有公开条目存在提案时只处理提案，不等于下架。`unpublish` 撤下误收条目、设为 rejected 并保留历史；`withdraw`记录确认停止领取并进入ended；默认需官方撤回依据，管理员明确实测可传basis=tested，保留原官方证据、记录实测依据与确认时间，不捏造实际claimEnd。
- 比赛、竞赛、黑客松及排名/投票的获奖奖励不收；同页独立的无需获奖赠额或科研/教学/创业资助按各自条款核验，不连带排除。明确独立资助的可疑空结果须复查或保留待处理。
- 脚本或批量预审只在用户授权范围写字段/内部记录/建议。用户说“不自动通过”时不运行 approve 或带 `--approve` 的编辑。平台准入授权与活动上架授权分开。

- 新增栏目：先在 `SECTIONS` 加一项，在 `checkOffer` 里给它依赖的字段加检查，再改前端。
- 新增字段：数据库迁移 → `offerIn` 校验 → `EDITABLE_FIELDS` → 审批表单 → 抽取提示词 → `checkOffer` → 本文第二节。
- 新增标签：`TAGS`（spec.ts）、`offerIn` 枚举、审批表单 `TAG_L`、抽取提示词，四处一起改。

线索处理过程另存于`leads.resolution`，不混进公开权益。`reviewing`会自动官方复核；技术受阻带下次重试，无法裁决转可操作审核任务，linked/rejected保留原因和关联。`leadReviewJobId`为入库传输控制，禁止自动上架，不能把相同生成ID当成同一活动。

## 八、持久身份与历史路由

第二、第三阶段的正式模型见 [主规格与补充](specs/dedupe-identity-2026-10-10/README.md)。实现已合并并发布，启用与历史回填的现场边界见[身份启用验证](dedupe-activation-2026-10-11.md)；具体运行开关和台账每次操作前重新核对。原有启发式作为召回特征；产品、独立领取机制、模型/池/轮次冲突与人工 different 是统一服务的先决约束，不能由标题、金额或模型 sameAs 绕过。

- 原始观察、抽取候选、活动实体、条款版本、审核决定和任务分别持久化；unknown 不等于零或没有限制。Evidence 原文保持原语言，公开字段只写权益与条件。
- business revision 管业务竞争，task revision 管 CAS/租约，material revision 管实质审核提醒，publication revision 管每次批准；lastSeen 与重复来源不推进审核提醒。A→B→A 恢复政策仍须一次新批准。
- 拒绝按 candidate/version/机制/别名等受控 scope 继承，保留原理由及证据；补足指定缺项或独立新轮次只可按规则进入待审，不自动发布。人工字段与决定不得由新抽取覆盖。
- offers/proposals 保持兼容投影，当前批准版本直到明确批准前不变。每次任务操作需要当前版本；stale 卡片或跨实体 version/decision 返回冲突，不能因 ID 存在就接受。
- 历史 offer 先独立回填，合并另需精确计划与显式主记录理由。逻辑合并保留原行、审核和送达 payload，通过 canonical 路由统一列表、统计、详情、旧 hash 与通知。未回填产品仍保留旧公开记录。
- pending/unknown 送达阻断相关重发；只有证明版本/轮次对应时继承 sent，不能伪造送达记录。撤销追加审计；新增证据、审核或发送引起冲突时保留新数据供人工处理。

现场效果须由冻结的人工标注脱敏语料与真实授权环境另验；合成 fixture 成绩不能当作线上 precision/recall。
